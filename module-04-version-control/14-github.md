# 第14章：GitHub — 你的代码云端家园

## 概念讲解

上一章我们学会了用 Git 在自己电脑上管理代码的历史。但如果你的电脑硬盘坏了呢？如果你想和朋友一起写代码呢？

这时候就需要 **GitHub** 了。

**GitHub** 是一个基于云端的代码托管平台。你可以把它理解成：

> **代码界的"百度网盘" + "微博"** — 既能安全存储你的代码，又能让全世界的开发者看到你的作品、参与你的项目。

全球超过 1 亿开发者在 GitHub 上协作，从个人小项目到 Linux 操作系统内核，都托管在这里。

---

## 核心概念

### 1. Remote Repository（远程仓库）

上一章我们创建的仓库只存在于你的电脑上，叫做 **本地仓库（Local Repository）**。GitHub 上的仓库叫做 **远程仓库（Remote Repository）**，它是你本地仓库在云端的一个副本。

> 类比：本地仓库是你手机里的照片，远程仓库是你同步到 iCloud/Google Photos 的云端备份。

### 2. Push（推送）与 Pull（拉取）

- **git push**：把本地的新提交"推"到 GitHub 上 — 就像把手机里的新照片上传到云端
- **git pull**：把 GitHub 上别人的新提交"拉"到你的电脑 — 就像把云端的更新下载到手机

### 3. Clone（克隆）

**git clone** 是把 GitHub 上一个完整的仓库复制到你的电脑上，包括所有的历史记录。

> 类比：别人分享了一个云盘链接，你把整个文件夹下载到了自己的电脑里。

### 4. Pull Request（拉取请求，简称 PR）

这是 GitHub 上最重要的协作功能。当你在自己的分支上完成了修改，你不是直接合并，而是发起一个 **Pull Request**，意思是："嘿，我做了这些改动，你们看看要不要合并进去？"

> 类比：你在公司写了一份方案，不是直接提交给客户，而是先发给组长审核。组长看完觉得没问题，才批准提交。这个审核流程就是 Pull Request。

## 实操步骤

### 第一步：注册 GitHub 账号

1. 访问 [github.com](https://github.com)
2. 点击 **Sign up**，填写用户名、邮箱、密码
3. 完成验证，选择免费计划（Free plan 完全够用）

> 小贴士：用户名要好好想，它会成为你的"开发者名片"。建议简洁、专业，比如用真名或有辨识度的昵称。

### 第二步：在 GitHub 上创建仓库

1. 点击右上角的 **"+"** → **New repository**
2. 填写仓库名称（比如 `my-first-project`）
3. 选择 Public（公开）或 Private（私有）
4. 勾选 "Add a README file"
5. 点击 **Create repository**

### 第三步：连接本地与远程（git remote）

如果你已经有一个本地仓库，把它和 GitHub 上的仓库关联起来：

```bash
git remote add origin https://github.com/你的用户名/my-first-project.git
```

`origin` 是远程仓库的默认别名，就像给你的云盘取了个名字叫"origin"。

查看当前关联的远程仓库：

```bash
git remote -v
```

### 第四步：推送代码（git push）

```bash
git push -u origin main
```

`-u` 的意思是"记住这个对应关系"，以后直接 `git push` 就行了。刷新 GitHub 页面，你会看到你的代码已经出现在云端了！

### 第五步：克隆别人的项目（git clone）

```bash
git clone https://github.com/某个用户/某个项目.git
```

这会在当前目录下创建一个新文件夹，里面是完整的项目代码和历史记录。

### 第六步：拉取更新（git pull）

当队友推送了新代码到 GitHub，你需要同步：

```bash
git pull origin main
```

> 养成习惯：**每次开始写代码之前，先 git pull**，就像上班第一件事先查收邮件。

## GitHub 的社交功能

### Issues（议题）

Issues 是项目的"待办清单"和"讨论区"。你可以用它来：

- 报告 Bug："登录按钮在手机上点不了"
- 提出功能建议："希望支持暗黑模式"
- 记录任务："需要优化首页加载速度"

> 类比：Issues 就像餐厅的意见本 — 顾客（用户）可以写下问题和建议，厨师（开发者）会逐条处理。

### README.md — 项目的门面

`README.md` 是你项目的"封面"和"说明书"，访客第一眼看到的就是它。一个好的 README 应该包含：

- 项目名称和简介
- 如何安装和使用
- 截图或演示
- 如何参与贡献

```markdown
# 我的天气应用

一个简单的天气查询网页应用。

## 安装步骤
1. 克隆仓库：`git clone https://github.com/xxx/weather-app.git`
2. 安装依赖：`npm install`
3. 启动项目：`npm start`

## 功能特性
- 输入城市名查询天气
- 显示未来 7 天预报
- 支持中英文切换
```

### GitHub Pages — 免费网站托管

GitHub 还能免费帮你托管静态网站！在仓库的 **Settings → Pages** 中开启，你的 HTML/CSS/JS 项目就能通过 `https://你的用户名.github.io/仓库名` 访问了。

> 这是展示个人作品集的绝佳方式，相当于免费获得了一个网站。

## 开源社区礼仪

GitHub 是全球最大的开源社区，参与时请遵守这些基本礼仪：

1. **先读文档**：在提 Issue 之前，先看看 README 和已有的 Issues
2. **礼貌沟通**：屏幕后面都是真人，保持友善和耐心
3. **遵守贡献指南**：很多项目有 `CONTRIBUTING.md` 文件，先阅读再动手
4. **提供足够信息**：报告 Bug 时说清楚环境、步骤、期望和实际结果
5. **尊重维护者的时间**：开源维护者大多是无偿贡献，不要催促

## AI 辅助练习

向 AI 助手提出以下请求来加深理解：

1. **"帮我写一个专业的 README.md 模板。"** — AI 能根据你的项目类型生成合适的模板
2. **"我 git push 的时候报错了，这是什么意思？"** — 把错误信息给 AI，它会帮你诊断
3. **"帮我写一个 Pull Request 的描述。"** — AI 能帮你组织清晰的 PR 说明
4. **"这个开源项目的 Issue 模板应该怎么填？"** — AI 能指导你规范地提交问题

### 动手练习

1. 注册一个 GitHub 账号（如果还没有的话）
2. 在 GitHub 上创建一个新仓库
3. 把上一章本地练习的项目推送到 GitHub
4. 编辑 `README.md`，写上项目介绍
5. 在 GitHub 网页上创建一个 Issue，记录一个你想添加的功能
6. 创建一个新分支，做些修改，提交并推送
7. 在 GitHub 上发起一个 Pull Request
8. （选做）开启 GitHub Pages，把一个简单的 HTML 页面部署上去

## 本章小结

| 概念 | 英文术语 | 类比 |
|------|----------|------|
| 远程仓库 | Remote Repository | 云端备份 |
| 推送 | Push | 上传照片到云端 |
| 拉取 | Pull | 从云端下载更新 |
| 克隆 | Clone | 下载整个云盘文件夹 |
| 拉取请求 | Pull Request (PR) | 提交方案等待审核 |
| 议题 | Issue | 意见本 / 待办清单 |

记住这个协作流程：**Clone/Pull（获取代码） → 创建分支 → 修改代码 → Push（推送） → Pull Request（请求合并） → Code Review（审核） → Merge（合并）**。这就是全世界开发团队每天都在使用的工作流。下一章，我们将学习 Git 的进阶技巧，让你的版本控制技能更上一层楼！
