# 第24章：项目规划与需求分析

## 从"我有个想法"到"我要开始写代码"

恭喜你走到了这一步！前面的章节里，你已经学会了编程的基础知识，掌握了如何与 AI 协作写代码。现在，是时候把这些技能组合起来，做一个真正属于你自己的项目了。

但是，先别急着打开编辑器。你有没有过这样的经历——兴冲冲地开始装修房子，结果装到一半发现插座位置留错了、柜子尺寸不对、水管走向有问题？写代码也是一样，**好的规划能帮你省下 80% 的返工时间**。

这一章，我们来聊聊如何把脑海中的想法，一步步变成可以执行的软件项目计划。

---

## 一、把想法变成需求：像写菜谱一样思考

### 想法 vs 需求

假设你想开一家餐厅。"我想开一家好吃的餐厅"是一个**想法**（idea）。而"提供 20 道菜品、能同时容纳 50 位客人、支持在线点餐"才是**需求**（requirements）。

软件开发也一样：

| 想法（模糊） | 需求（具体） |
|---|---|
| "做一个博客" | 用户可以发布文章、文章支持 Markdown 格式、有标签分类功能 |
| "做一个 Todo 应用" | 用户可以注册登录、创建/编辑/删除待办事项、按分类筛选 |
| "做一个 AI 工具" | 用户输入一段文字，AI 返回摘要，支持中英文 |

### 用 AI 帮你做需求分析

这是 AI 编程助手最擅长的事情之一！你可以这样问 AI：

```
我想做一个个人博客网站，目标用户是想展示作品的设计师。
请帮我列出：
1. 核心功能（必须有的）
2. 进阶功能（有了更好的）
3. 可能的技术难点
```

AI 会帮你梳理出一个结构清晰的需求列表，比你自己一个人想要全面得多。这就像有一个经验丰富的产品经理坐在你旁边，帮你查漏补缺。

## 二、技术选型（Technology Stack Selection）：选对工具很重要

### 什么是技术栈（Tech Stack）？

技术栈就是你用来构建项目的"工具箱"。就像盖房子需要选择用砖头还是木头、用水泥还是钢结构一样，做软件也需要选择：

- **前端框架**（Frontend Framework）：用什么来写用户看到的界面？React？Vue？还是纯 HTML？
- **后端框架**（Backend Framework）：用什么来处理数据和逻辑？Node.js？Python？
- **数据库**（Database）：数据存在哪里？SQLite？PostgreSQL？MongoDB？
- **部署平台**（Deployment Platform）：做好了放在哪里让别人访问？Vercel？Railway？

### 让 AI 帮你做技术选型

你可以直接问 AI：

```
我是一个编程初学者，想做一个个人博客网站。
我的情况：
- 学过一点 HTML/CSS/JavaScript
- 希望部署简单
- 不需要复杂的后端
请推荐适合我的技术栈，并说明原因。
```

AI 会根据你的经验水平和项目需求，给出量身定制的建议。关键是——**不要追求最热门的技术，要选最适合你当前水平的技术**。

就像学开车，你不需要一上来就开 F1 赛车，一辆自动挡的家用车就能让你安全地从 A 点到 B 点。

## 三、MVP 思维：先做一个"能用"的版本

### 什么是 MVP（Minimum Viable Product，最小可行产品）？

MVP 是创业圈的一个重要概念，意思是：**先做出最简单的、但真正能用的版本**。

打个比方：你想开一家咖啡店。MVP 不是装修豪华、有 50 种饮品的大店，而是一个街角的小摊位，只卖美式和拿铁。先验证"有没有人愿意买你的咖啡"，再考虑扩张。

软件开发中的 MVP 思维：

```
❌ 错误思路：
"我要做一个完美的博客——要有评论系统、搜索功能、多语言支持、
 暗色模式、RSS 订阅、SEO 优化……"
→ 三个月后还没做完，已经失去兴趣

✅ 正确思路：
"我先做一个能展示文章的页面，部署上线。"
→ 一周内完成，有了成就感，再慢慢加功能
```

### MVP 的核心原则

1. **只做核心功能**：问自己"没有这个功能，产品还能用吗？"如果答案是"能"，先不做。
2. **快速上线**：一个部署了的半成品，比一个停留在本地的"完美"项目有价值得多。
3. **迭代改进**（Iterate）：上线后根据反馈和自己的想法，持续优化。

## 四、用户故事（User Stories）与功能优先级

### 用户故事：站在用户的角度想问题

用户故事（User Story）是一种简单的需求描述方式，格式是：

> **作为**（一个什么样的用户），**我想要**（什么功能），**以便**（达到什么目的）。

举例：

- 作为一个**博客读者**，我想要**按标签筛选文章**，以便**快速找到感兴趣的内容**。
- 作为一个**博客作者**，我想要**用 Markdown 写文章**，以便**高效地排版内容**。
- 作为一个**求职者**，我想要**展示我的项目作品**，以便**让面试官了解我的能力**。

这种方式能帮你跳出"开发者视角"，真正思考用户需要什么。

### 功能优先级：MoSCoW 方法

把所有功能分成四类：

| 优先级 | 含义 | 举例（博客项目） |
|---|---|---|
| **Must have**（必须有） | 没有就不能用 | 展示文章、基本导航 |
| **Should have**（应该有） | 很重要但不致命 | 标签分类、响应式设计 |
| **Could have**（可以有） | 锦上添花 | 暗色模式、搜索功能 |
| **Won't have**（暂时不做） | 这次先不考虑 | 评论系统、多语言 |

让 AI 帮你排优先级：

```
以下是我的博客项目的功能列表，请帮我用 MoSCoW 方法排列优先级，
并说明原因：
- 文章展示
- 标签分类
- 搜索功能
- 暗色模式
- 评论系统
- RSS 订阅
- 响应式设计
- SEO 优化
```

## 五、项目结构设计（Project Structure）

### 文件夹就像抽屉

一个好的项目结构，就像一个整理得当的衣柜——袜子放在袜子的抽屉里，衬衫挂在衬衫的区域。你不需要翻遍整个衣柜才能找到想穿的衣服。

典型的前端项目结构：

```
my-blog/
├── src/
│   ├── components/    # 可复用的 UI 组件（按钮、导航栏等）
│   ├── pages/         # 页面（首页、文章页、关于页）
│   ├── styles/        # 样式文件
│   └── utils/         # 工具函数
├── public/            # 静态资源（图片、图标）
├── package.json       # 项目配置
└── README.md          # 项目说明
```

让 AI 帮你生成项目结构：

```
我要用 Next.js + Tailwind CSS 做一个个人博客，
请帮我设计项目的文件夹结构，并解释每个文件夹的用途。
```

## 六、线框图与原型（Wireframing & Prototyping）

### 先画草图，再写代码

在盖房子之前，建筑师会先画图纸。同样，在写代码之前，你应该先知道页面长什么样。

**线框图**（Wireframe）就是网页的"草图"，不需要颜色和细节，只需要表明：

- 页面有哪些区域？
- 导航栏在哪里？
- 内容怎么排列？

你甚至可以用纸和笔画，或者用简单的工具如 Excalidraw、Figma 的免费版。

更棒的是，你可以让 AI 帮你生成线框图的文字描述：

```
请帮我描述一个个人博客首页的线框图布局：
- 顶部导航栏
- 文章列表（卡片式）
- 侧边栏（个人简介 + 标签云）
- 底部页脚
```

然后把这个描述交给 AI，让它直接帮你生成对应的 HTML/CSS 代码！

## 本章小结

在动手写代码之前，花点时间做规划，就像出远门前看一眼地图。你不需要规划得事无巨细，但至少要知道：

1. **你要做什么**：把想法转化为具体的需求列表
2. **用什么做**：选择适合自己水平的技术栈（Tech Stack）
3. **先做什么**：用 MVP 思维确定第一步，用 MoSCoW 方法排优先级
4. **长什么样**：画一个简单的线框图，心里有数
5. **代码放哪里**：设计合理的项目结构

最重要的一点：**AI 是你规划阶段的最佳伙伴**。它见过成千上万个项目，能帮你避开很多新手常踩的坑。大胆地把你的想法告诉它，让它帮你梳理、补充、优化。

下一章，我们就要正式动手了——一起做一个个人博客网站！
