# 第8章：其他 AI 编程工具

## 概念讲解

上一章我们详细学习了 Claude Code。但 AI 编程工具的世界远不止于此——就像交通工具不只有汽车，还有自行车、地铁和飞机，**不同的工具适合不同的场景**。

这一章，我们来认识几个主流的 AI 编程工具，帮你建立一个完整的"工具箱"。等你了解了每个工具的特点，就能根据自己的需求选择最合适的那一个。

## Cursor — AI 原生代码编辑器

### 它是什么

**Cursor** 是一个基于 VS Code 打造的 **AI-native IDE（AI 原生集成开发环境）**。如果说 Claude Code 像一个在命令行里工作的驻场工程师，那 Cursor 就像把这个工程师直接**安排到了你的编辑器里面**。

### 类比说明

想象你在写作文。普通编辑器就像一张白纸和一支笔——你自己写。Cursor 就像有一个坐在旁边的写作老师，你写到一半他就能猜到你接下来要写什么，还能帮你改句子、补段落。

### 核心功能

- **Tab 智能补全**：你打几个字，它自动预测接下来要写的代码，按 Tab 键就能采纳。比传统的代码补全聪明得多——它理解你的意图，不是简单的关键词匹配。

- **内联编辑（Inline Edit）**：选中一段代码，按 `Ctrl+K`，用自然语言描述你要怎么改，它直接帮你改好。

- **Chat 面板**：侧边栏有一个聊天窗口，可以和 AI 对话讨论代码，类似在编辑器内嵌了一个 Claude/ChatGPT。

- **Composer 模式**：可以同时编辑多个文件来完成一个完整功能，AI 理解文件之间的关系。

- **代码库索引（Codebase Indexing）**：Cursor 会扫描你整个项目，AI 回答问题时能参考所有文件，而不只是当前打开的那个。

### 快速上手

1. 从 [cursor.com](https://cursor.com) 下载安装
2. 它的界面和 VS Code 几乎一模一样，如果你用过 VS Code 就无缝切换
3. 可以直接导入 VS Code 的配置、插件和快捷键
4. 免费版每月有一定的使用额度，足够学习使用

## GitHub Copilot — 你的 AI 结对程序员

### 它是什么

**GitHub Copilot** 是 GitHub 和 OpenAI 合作推出的 AI 编程助手。它以**插件（Extension）** 的形式安装在 VS Code 等编辑器中。

### 类比说明

如果你学过音乐，Copilot 就像一个**即兴伴奏师**——你弹了几个音符（写了几行代码），它就能猜到你接下来的旋律（代码逻辑），然后自动帮你弹出来。你觉得好就用，觉得不对就忽略。

### 核心功能

- **行内代码建议（Inline Suggestions）**：你打字的同时，Copilot 以灰色文字显示建议的代码，按 Tab 接受。

- **Copilot Chat**：类似 ChatGPT 的对话窗口，可以问编程问题、让它解释代码、生成测试等。

- **多编辑器支持**：VS Code、JetBrains 系列（IntelliJ、PyCharm 等）、Neovim 都能用。

- **Copilot Workspace**：基于 GitHub Issue 自动规划和实现代码更改，面向更完整的工作流程。

### 快速上手

1. 需要一个 GitHub 账号
2. 在 VS Code 中搜索安装 "GitHub Copilot" 插件
3. 登录 GitHub 账号并授权
4. 开始写代码，Copilot 会自动给出建议
5. 学生可以申请免费使用（GitHub Education）

## OpenAI Codex CLI — OpenAI 的命令行工具

### 它是什么

**Codex CLI** 是 OpenAI 推出的开源命令行编程助手，和 Claude Code 类似，直接在终端中使用。它基于 OpenAI 的模型来帮你读代码、写代码和执行命令。

### 类比说明

如果 Claude Code 是一个会说中文的驻场工程师，那 Codex CLI 就是另一家公司派来的驻场工程师——做的事情类似，但风格和能力侧重点不同。

### 核心功能

- 在终端中用自然语言描述任务
- 能读取和编辑本地文件
- 支持运行 shell 命令
- 开源项目，可以自行修改和扩展

### 快速上手

```bash
# 安装
npm install -g @openai/codex

# 使用（需要 OpenAI API Key）
export OPENAI_API_KEY="your-key-here"
codex
```

## 工具对比总览

该选哪个？看这张表：

| 特性 | Claude Code | Cursor | GitHub Copilot | Codex CLI |
|------|------------|--------|---------------|-----------|
| 类型 | 命令行工具 | 独立编辑器 (IDE) | 编辑器插件 | 命令行工具 |
| 交互方式 | 自然语言对话 | 对话 + 内联编辑 + 补全 | 内联补全 + 对话 | 自然语言对话 |
| 能否直接改文件 | 能 | 能 | 能（有限） | 能 |
| 能否运行命令 | 能 | 通过终端 | 不能 | 能 |

## 如何选择适合你的工具

### 场景1：你是完全的初学者

**推荐：Cursor**

理由：图形界面友好、上手门槛最低。你可以一边写代码一边和 AI 聊天，像带着辅导老师一起做作业。

### 场景2：你已经习惯了 VS Code

**推荐：GitHub Copilot + VS Code**

理由：不用换编辑器，安装一个插件就能用。Copilot 的行内补全体验非常流畅，写代码时几乎感觉不到它的存在——直到你发现它已经帮你写好了下一行。

### 场景3：你喜欢命令行，想要更强的 AI 控制力

**推荐：Claude Code**

理由：它能读取整个项目、运行命令、直接修改文件。适合需要做复杂重构、调试、或项目级别代码生成的场景。

### 场景4：你想同时用多个工具

**完全可以！** 很多开发者的工作方式是：

- 用 **Cursor** 或带 **Copilot** 的 VS Code 日常写代码
- 遇到复杂问题时，启动 **Claude Code** 进行深度对话和项目级操作
- 需要快速问一个问题时，打开网页版 **Claude** 或 **ChatGPT**

这就像出行时——短途骑自行车，中途坐地铁，长途坐飞机。**工具不冲突，按需组合才是最聪明的做法。**

## AI 辅助练习

1. **安装体验**：选择一个你还没用过的工具（Cursor 或 GitHub Copilot），安装它并完成一个简单任务——例如用 Python 写一个"石头剪刀布"小游戏。感受不同工具的交互方式有什么区别。

2. **同题对比**：把同一个编程问题（比如"用 Python 写一个简单的密码生成器"）分别在 Claude Code 和 Cursor（或 Copilot）中完成。对比：
   - 哪个上手更快？
   - 哪个生成的代码质量更好？
   - 哪个交互方式你更喜欢？

3. **工具组合练习**：尝试一个"混合工作流"——先用 Claude Code 创建项目骨架，然后用 Cursor 或 VS Code + Copilot 来补充细节和日常开发。体会不同工具配合使用的感觉。

## 本章小结

| 工具 | 一句话总结 | 最适合场景 |
|------|-----------|-----------|
| Claude Code | 命令行里的 AI 驻场工程师 | 项目级操作、复杂调试和重构 |
| Cursor | 自带 AI 的智能编辑器 | 日常编码、初学者友好 |
| GitHub Copilot | 编辑器里的即兴伴奏师 | 已有 VS Code 习惯的开发者 |
| Codex CLI | OpenAI 的命令行助手 | 喜欢开源、已有 OpenAI API 的用户 |

> **核心理念**：没有"最好的"工具，只有"最适合你当前场景的"工具。先选一个用起来，等熟悉了再尝试其他的。工具是为你服务的——不要在选择工具上花太多时间，花时间在真正写代码和学习上。
