# 第6章：提示词工程（Prompt Engineering）基础

## 概念讲解

上一章我们了解了 LLM 是什么。现在的问题是：**怎么跟它说话，才能得到最好的回答？**

这就像去餐厅点菜。你对服务员说"随便来点吃的"，他可能端上一盘你完全不想吃的东西。但如果你说"我想要一份不辣的、带米饭的牛肉套餐"，你得到满意结果的概率就大多了。

**提示词工程（Prompt Engineering）** 就是研究如何写出好的指令（Prompt，提示词），让 AI 给出更准确、更有用的回答。这不是什么高深的技术——它的本质就是**清晰地表达你的需求**。

## 类比说明：给实习生布置任务

把 AI 想象成一个**聪明但没有背景知识的实习生**。他能力很强，但他不知道你的项目、你的偏好、你的具体情况。你布置任务时说得越清楚，他完成得越好。

| 差的布置方式 | 好的布置方式 |
|------------|------------|
| "帮我写个网页" | "帮我用 HTML+CSS 写一个个人简历页面，包含姓名、照片、工作经历三个部分，风格简洁现代" |
| "这段代码有问题" | "这段 Python 代码运行时报了 TypeError 错误（错误信息附在下面），请帮我找出原因并修复" |
| "教我编程" | "我是完全零基础的初学者，请用简单的中文教我 Python 的变量和数据类型，每个概念给一个生活中的例子" |

看出区别了吗？好的 Prompt 包含了**背景、具体需求和期望格式**。

## 实操步骤：五个核心技巧

### 技巧一：提供角色设定（Role Setting）

告诉 AI "你是谁"，它就会按照那个角色来回答。

```
你是一位有10年经验的 Python 高级工程师，擅长用简单的语言向初学者解释复杂概念。
请解释什么是"装饰器（Decorator）"。
```

这就像在餐厅告诉厨师"我带了一个小孩"——他自然会把菜做得口味清淡些。

### 技巧二：结构化提示（Structured Prompt）

把你的需求用清晰的结构组织起来，而不是写成一大段话。

```
## 任务
帮我写一个 Python 函数

## 功能要求
- 输入：一个包含学生成绩的列表（List）
- 处理：计算平均分、最高分、最低分
- 输出：返回一个包含三个值的字典（Dictionary）

## 其他要求
- 添加中文注释
- 处理空列表的边界情况
- 使用 Type Hints（类型注解）
```

结构化的 Prompt 就像填表格——每个空格都填清楚了，出错的概率就很低。

### 技巧三：少样本示例（Few-shot Examples）

给 AI 看几个例子，它就能明白你想要什么格式和风格。

```
请按照以下格式为 Python 内置函数写说明：

示例1：
函数：len()
作用：计算对象的长度或元素个数
用法：len("hello") → 5
适合场景：需要知道列表有多少元素、字符串有多少字符时

示例2：
函数：type()
作用：返回对象的数据类型
用法：type(42) → <class 'int'>
适合场景：调试时不确定一个变量是什么类型

现在请按同样格式写：range()、print()、input()
```

这就像给新员工看几份已完成的报告——"照着这个格式写"。

### 技巧四：分步要求（Step by Step）

遇到复杂问题时，要求 AI 分步骤思考和回答。

```
我想用 Python 做一个简单的待办事项（To-Do List）命令行程序。
请分步骤帮我完成：

第1步：先设计数据结构，解释为什么这样设计
第2步：实现添加任务的功能
第3步：实现显示所有任务的功能
第4步：实现删除任务的功能
第5步：把所有功能整合成完整程序

每一步都先解释思路，再给出代码。
```

把大象装冰箱分三步：打开门、放进去、关上门。编程也是一样——**拆解问题是解决问题的第一步**。

### 技巧五：迭代优化（Iteration）

第一次的回答不满意？没关系，继续追问和调整。

```
第一轮："帮我写一个排序函数"
→ AI 给了一个基本实现

第二轮："能不能加上对空列表的处理？"
→ AI 添加了边界检查

第三轮："请加上详细的中文注释，并写几个测试用例"
→ AI 补充了注释和测试

第四轮："能不能用更简洁的写法重构一下？"
→ AI 优化了代码
```

这就像改论文——第一稿、第二稿、第三稿，**每次对话都让结果更接近你想要的**。

## 编程场景的常用 Prompt 模板

以下是几个你会经常用到的模板，直接复制修改即可：

### 模板1：请求解释代码
```
请用简单的中文逐行解释以下代码的作用，假设我是一个编程初学者：

[粘贴你的代码]
```

### 模板2：调试求助
```
以下代码运行时报错了：

代码：
[粘贴代码]

报错信息：
[粘贴错误信息]

请分析错误原因，并给出修复后的完整代码。
```

### 模板3：从零实现功能
```
请用 [编程语言] 实现以下功能：
- 功能描述：[你想实现什么]
- 输入：[输入是什么]
- 输出：[期望输出是什么]
- 注意事项：[任何特殊要求]

请添加详细注释，并提供使用示例。
```

### 模板4：代码审查
```
请审查以下代码，从这几个方面给出改进建议：
1. 代码是否有 Bug
2. 是否有性能问题
3. 代码可读性如何
4. 有没有更好的写法

[粘贴代码]
```

## AI 辅助练习

1. **对比实验**：用一个模糊的 Prompt 和一个精确的 Prompt 分别向 AI 提问同一个编程问题，对比两次回答的质量差异。例如：
   - 模糊版："写个 Python 程序"
   - 精确版："用 Python 写一个猜数字游戏，随机生成1-100的数字，用户输入猜测，程序提示'大了'或'小了'，猜对后显示猜了几次"

2. **角色实验**：同一个问题，分别设定不同角色。例如问"什么是 API"，一次让 AI 扮演"给5岁小孩解释的幼儿园老师"，一次扮演"给计算机专业学生讲课的大学教授"，感受回答的区别。

3. **迭代练习**：向 AI 提出一个编程需求，然后至少追问 3 轮来完善结果。体验"对话式编程"的过程。

## 本章小结

| 技巧 | 核心思路 | 类比 |
|------|---------|------|
| 角色设定（Role Setting） | 告诉 AI 以什么身份回答 | 告诉厨师"这顿饭是给小孩吃的" |
| 结构化提示（Structured Prompt） | 用清晰的格式组织需求 | 填表格而不是写大段文字 |
| 少样本示例（Few-shot） | 给 AI 看几个例子 | 给新员工看已完成的报告范本 |
| 分步要求（Step by Step） | 让 AI 分步思考和执行 | 把大象装冰箱分三步 |
| 迭代优化（Iteration） | 多轮对话逐步完善 | 论文从初稿改到终稿 |

> **记住**：Prompt Engineering 没有唯一正确答案，关键是**清晰、具体、有结构**。多试几次，你就会找到自己的沟通风格。
