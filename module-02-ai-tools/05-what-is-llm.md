# 第5章：大语言模型（LLM）是什么

## 概念讲解

你有没有遇到过一个特别博学的朋友？不管你问他什么——历史、科学、写作、编程——他都能侃侃而谈，给你一个看起来挺靠谱的回答。**大语言模型（Large Language Model，简称 LLM）** 就像这样一个"超级博学的朋友"，只不过它是一个计算机程序。

那它到底是怎么做到的呢？

## 类比说明：一个读了整个图书馆的学生

想象有一个学生，他从小到大读了全世界几乎所有的书、文章、网页和代码。他没有"记住"每一句话，但他从中学到了**语言的规律**——什么词通常跟在什么词后面，什么样的回答对应什么样的问题。

当你问他"Python 怎么打印一句话？"，他不是去翻书找答案，而是根据过去读过的无数代码示例，**预测**出最合理的下一个词，一个词一个词地"说"出答案：`print("Hello")`。

这就是 LLM 的核心原理：**通过海量文本训练，学习语言规律，然后一个词一个词地预测和生成回答。**

## 三个关键概念

### 1. Token（词元）

LLM 不是按"字"或"词"来理解文字的，而是把文本切成一个个小片段，叫做 **Token（词元）**。

打个比方：你吃饭的时候不是整碗饭塞进嘴里，而是一口一口吃。Token 就是 LLM "吃"文字的一小口。

- 英文里，一个单词大约是 1-2 个 Token
- 中文里，一个汉字通常是 1-2 个 Token
- `"Hello World"` 大约是 2 个 Token
- `"你好世界"` 大约是 4 个 Token

为什么这很重要？因为 **Token 数量直接决定了费用和速度**——用得越多，花的钱越多，等待时间越长。

### 2. Context Window（上下文窗口）

**Context Window（上下文窗口）** 就是 LLM 一次能"看到"多少内容。

类比：想象你在和朋友打电话。如果你朋友的记忆只有最近 5 分钟的对话，那超过 5 分钟前说的话他就忘了。Context Window 就是 LLM 的"短期记忆容量"。

| 模型 | 上下文窗口大小 |
|------|---------------|
| GPT-4o | 128K Token（约 10 万字） |
| Claude Sonnet/Opus | 200K Token（约 15 万字） |
| Gemini 1.5 Pro | 1M Token（约 75 万字） |

窗口越大，LLM 就能同时处理越长的文档、越大的代码库。

### 3. Temperature（温度）

**Temperature（温度）** 控制 LLM 回答的"创造性"程度。

类比：想象一个厨师做菜。温度设为 0，他每次严格按菜谱做，做出来的菜完全一样。温度设为 1，他会即兴发挥，加点这个、减点那个，每次做出来的味道都不同。

- **温度低（0-0.3）**：回答更稳定、更可预测，适合写代码、做数学题
- **温度高（0.7-1.0）**：回答更有创意、更多样，适合写故事、头脑风暴

写代码时，通常建议用**较低的温度**，因为我们需要准确、一致的答案。

## 主流模型对比

目前市面上有几个主要的 LLM，就像手机市场有 iPhone、三星和华为一样：

| 特性 | ChatGPT (OpenAI) | Claude (Anthropic) | Gemini (Google) |
|------|------------------|-------------------|-----------------|
| 擅长领域 | 通用能力均衡 | 长文本、编程、细致分析 | 多模态、大窗口 |
| 编程能力 | 强 | 非常强 | 强 |
| 中文支持 | 好 | 好 | 好 |
| 免费使用 | ChatGPT 免费版 | claude.ai 免费版 | Gemini 免费版 |
| 特色工具 | ChatGPT + Canvas | Claude Code（命令行） | Gemini in Android Studio |

**选择建议**：刚入门时不必纠结，挑一个先用起来。本课程主要使用 **Claude**，因为它在编程辅助方面表现出色，而且有专门的命令行工具 Claude Code。

## AI 能做什么，不能做什么

### 能做的事（强项）

- 解释代码和概念——你的 24 小时私人老师
- 生成代码片段——告诉它需求，它帮你写
- 找 Bug（调试）——把报错信息丢给它
- 翻译和重构代码——从一种风格改成另一种
- 回答编程问题——比搜索引擎更直接

### 不能做的事（局限）

- **不保证 100% 正确**——它会"一本正经地胡说八道"（Hallucination，幻觉），所以永远要验证它的回答
- **不了解最新信息**——它的知识有截止日期
- **不理解你的完整项目**——它只能看到你给它的内容（Context Window 范围内）
- **不能替代思考**——它是工具，不是大脑；你需要理解它生成的代码

> 记住一个黄金法则：**AI 是你的副驾驶（Copilot），不是司机。方向盘始终在你手里。**

## AI 辅助练习

1. **感受 Token**：打开 [ChatGPT](https://chat.openai.com) 或 [Claude](https://claude.ai)，输入"请用 Python 写一个计算器程序"，观察它是一个词一个词地"打"出来的——这就是逐 Token 生成的过程。

2. **体验温度差异**：分别问 AI "给我的猫起个名字"三次。你会发现每次回答都不同（因为默认温度较高）。然后问"1+1等于几"三次，回答几乎一样（因为这类问题的答案确定性很高）。

3. **测试局限性**：问 AI"今天的天气怎么样？"或者"我桌子上放了什么东西？"——感受它无法获取实时信息和物理世界信息的局限。

## 本章小结

| 概念 | 一句话解释 |
|------|-----------|
| LLM | 通过海量文本训练、能预测和生成语言的 AI 程序 |
| Token（词元） | LLM 处理文字的最小单位，影响费用和速度 |
| Context Window（上下文窗口） | LLM 一次能处理的最大文本量，即"短期记忆" |
| Temperature（温度） | 控制回答的创造性程度，写代码建议用低温度 |
| Hallucination（幻觉） | AI 自信地给出错误信息的现象，需要人工验证 |
