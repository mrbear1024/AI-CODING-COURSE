# 第18章：后端开发入门

## 引言：网页背后的"厨房"

上一章我们学了前端——用户看到的网页界面。但你有没有想过，当你在淘宝搜索一件商品，搜索结果是从哪里来的？当你登录微信，服务器怎么知道你的密码是对的？

这些工作都由**后端（Backend）**来完成。

**把一个网站想象成一家餐厅：**
- **前端**是餐厅的大堂——装修漂亮、菜单精美、服务员礼貌周到
- **后端**是餐厅的厨房——客人看不到，但所有的核心工作都在这里完成
- **数据库**是食材仓库——厨房需要什么食材，就去仓库里取

顾客（用户）只和大堂（前端）打交道，但真正"做菜"（处理数据、执行逻辑）的是厨房（后端）。

## 核心概念讲解

### 服务器（Server）到底是什么？

**服务器**这个词听起来很高大上，但本质上它就是一台**一直开着的电脑**，上面运行着一个程序，随时等待并响应别人的请求。

就像一家 24 小时营业的餐厅——不管什么时候有客人来点餐，厨房都在待命。

你自己的电脑也可以当服务器！当你在本地运行一个后端程序时，你的电脑就变成了一个"小服务器"。

### 用什么语言写后端？

很多编程语言都能写后端。对于初学者，最常见的两个选择：

**选项一：Node.js + Express**
- Node.js 让 JavaScript 不仅能在浏览器里跑，还能在服务器上跑
- Express 是一个轻量级的后端框架（Framework），帮你快速搭建服务器
- 优势：如果你已经学了 JavaScript，前后端可以用同一种语言

**选项二：Python + FastAPI**
- Python 语法简洁易懂，非常适合初学者
- FastAPI 是一个现代的 Python 后端框架，速度快、文档好
- 优势：Python 在 AI 和数据领域也很强，一举两得

### 路由（Routes）—— 给请求指路

当一个请求到达服务器，服务器怎么知道该做什么？这就是**路由（Routing）**的工作。

**把路由想象成餐厅的前台接待员：**
- 客人说"我要吃饭" → 带到用餐区
- 客人说"我要结账" → 带到收银台
- 客人说"我找经理" → 带到经理办公室

在代码中，路由就是把**不同的 URL 请求**分配给**不同的处理函数**：

**Express（JavaScript）示例：**
```javascript
const express = require('express');
const app = express();

// 路由：当有人访问首页时
app.get('/', (req, res) => {
    res.send('欢迎来到我的网站！');
});

// 路由：当有人请求用户列表时
app.get('/api/users', (req, res) => {
    res.json([
        { id: 1, name: '小明' },
        { id: 2, name: '小红' }
    ]);
});

// 启动服务器，监听 3000 端口
app.listen(3000, () => {
    console.log('服务器已启动，访问 http://localhost:3000');
});
```

**FastAPI（Python）示例：**
```python
from fastapi import FastAPI

app = FastAPI()

# 路由：当有人访问首页时
@app.get("/")
def read_root():
    return {"message": "欢迎来到我的网站！"}

# 路由：当有人请求用户列表时
@app.get("/api/users")
def get_users():
    return [
        {"id": 1, "name": "小明"},
        {"id": 2, "name": "小红"}
    ]
```

看到了吗？两种语言的思路是一样的：**定义 URL 路径 + 定义处理函数**。

### 请求处理与返回 JSON 数据

后端最常做的事情就是：**收到请求 → 处理数据 → 返回结果**。

而现代 Web 开发中，后端返回的数据格式几乎都是 **JSON（JavaScript Object Notation）**。JSON 长这样：

```json
{
    "success": true,
    "data": {
        "id": 42,
        "title": "学习后端开发",
        "completed": false
    }
}
```

为什么用 JSON？因为它**结构清晰、人和机器都能读懂**，就像一种"通用语言"，前端和后端都说得明白。

### 中间件（Middleware）—— 流水线上的质检员

**中间件**是后端开发中一个非常重要的概念。它是请求到达最终处理函数**之前**，经过的一系列"检查站"。

**想象一下机场安检：**
- 你要登机（最终目标 = 处理请求）
- 但在此之前，你需要经过：值机柜台 → 安检门 → 证件检查 → 登机口
- 每一个环节就是一个"中间件"

在后端中，中间件常用来做这些事：

```javascript
// 中间件1：记录每个请求的时间（日志）
app.use((req, res, next) => {
    console.log(`${new Date().toISOString()} - ${req.method} ${req.url}`);
    next(); // 通过！进入下一个环节
});

// 中间件2：解析 JSON 格式的请求体
app.use(express.json());

// 中间件3：检查用户是否登录
function checkAuth(req, res, next) {
    if (req.headers.authorization) {
        next(); // 有凭证，放行
    } else {
        res.status(401).json({ error: '请先登录' }); // 没凭证，拦截
    }
}
```

关键是那个 `next()` 函数——它的意思是"检查通过，交给下一个环节"。如果某个中间件不调用 `next()`，请求就会被拦在那里。

### 认证（Authentication）—— 证明"你是你"

当用户登录时，服务器怎么验证身份？最常见的方式是 **Token（令牌）认证**：

1. 用户发送用户名和密码
2. 服务器验证正确后，生成一个 **Token**（一串加密的字符串）
3. 把 Token 返回给用户
4. 之后用户每次请求都带上这个 Token
5. 服务器检查 Token 是否有效

**这就像游乐园的手环：** 你在入口买票（登录），工作人员给你戴上一个手环（Token）。之后你玩任何项目，只要出示手环就行，不用每次都重新买票。

目前最流行的 Token 方案是 **JWT（JSON Web Token）**。

## 实操步骤：用 AI 搭建一个简单的 API

让我们动手做一个"待办事项 API"！

**第一步：选择你的工具**
- 如果你熟悉 JavaScript：用 Node.js + Express
- 如果你熟悉 Python：用 Python + FastAPI

**第二步：向 AI 提出需求**

> "请帮我用 Express（或 FastAPI）创建一个待办事项 API，要求：
> 1. GET /api/todos - 获取所有待办事项
> 2. POST /api/todos - 创建新的待办事项
> 3. PUT /api/todos/:id - 更新某个待办事项
> 4. DELETE /api/todos/:id - 删除某个待办事项
> 数据先存在内存中（不需要数据库）。请给出完整的代码和运行步骤。"

**第三步：** 按照 AI 给的步骤运行代码

**第四步：** 用浏览器或工具测试你的 API
- 在浏览器中访问 `http://localhost:3000/api/todos`（测试 GET）
- 让 AI 教你用 `curl` 命令或 Postman 工具测试 POST、PUT、DELETE

## AI 辅助练习

**练习 1：添加中间件**
> "请给我的 Express（或 FastAPI）项目添加一个日志中间件，记录每个请求的方法、URL 和时间。"

**练习 2：添加简单认证**
> "请给我的 API 添加一个简单的认证功能：需要在请求头中带上 API Key 才能访问。没有 Key 的请求返回 401 错误。"

**练习 3：错误处理**
> "请帮我添加错误处理：当请求一个不存在的待办事项 ID 时，返回 404 错误和友好的提示信息。"

**练习 4：理解代码**
> 把完整代码发给 AI，问："请用中文逐行解释这段后端代码，特别说明每个路由做了什么事情。"

## 本章小结

| 概念 | 一句话总结 |
|------|-----------|
| 后端/服务器 | 网站的"厨房"，处理数据和业务逻辑 |
| Node.js / Express | 用 JavaScript 写后端的流行方案 |
| Python / FastAPI | 用 Python 写后端的现代方案 |
| 路由（Routes） | 把不同的请求分配给不同的处理函数 |
| JSON | 前后端之间交换数据的通用格式 |
| 中间件（Middleware） | 请求处理流水线上的"检查站" |
| 认证（Authentication） | 验证用户身份，常用 Token/JWT 方式 |

后端开发就像管理一家餐厅的厨房：你要规划好厨房的分工（路由），设置好质检流程（中间件），确认来点餐的人身份（认证），然后把做好的菜（数据）端出去。有了 AI 的帮助，即使你是新手厨师，也能很快做出像样的菜来！
